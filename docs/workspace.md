# Web workspace

Kinmesh serves a React workspace from the same Fastify origin as its authenticated HTTP API. React and Radix Tabs provide the component and accessible navigation foundation. The execution view uses the official `@ag-ui/core` 1.0 protocol and SDK validators through a small React headless snapshot consumer. It neither embeds T3 UI code nor connects the browser to a provider.

## Start and sign in

Use Node 24:

```sh
npm ci
npm run build
npm run setup
npm start
```

Open `http://127.0.0.1:3000/`. Sign in, or select **First owner setup** on a new installation. Setup requires the private setup secret generated by `npm run setup`; enter it only in the local trusted form, never in chat, URLs or a public terminal transcript. Username/password/team validation and the one-time claim are enforced by the existing setup endpoint. No anonymous caller can claim ownership. After setup, explicitly sign in. The masked CLI `npm run onboard` remains an alternative.

The browser keeps credentials out of local/session storage. Password/setup fields are masked; request credentials exist only in form/request memory and the server's protected session mechanism. Setup authorization uses the existing one-time secret, not a provider or agent token. Sign-out clears the encrypted HttpOnly, SameSite=Strict cookie and the displayed workspace. For remote use, deploy behind same-origin HTTPS with `KINMESH_ORIGIN` configured; see [security](security.md).

Build before source `npm start` to supply `web-dist/`. `npm run build` typechecks all first-party TypeScript/TSX, builds Vite assets, compiles server code and stages assets/migrations under `dist/`. The compiled server can run from `dist/src/server/main.js` with the same environment configuration. Without built assets, `/` returns 503 with a build instruction; `/api/*` and `/health` keep their API behavior. Only `/` and the built `/assets/` tree are served; no repository, credentials or generic SPA fallback is exposed.

For UI development, run `npm run web:watch` alongside the normal `npm start` after the initial build. Vite rebuilds public assets on source edits; refresh the browser after a completed build. All requests keep the same integrated origin, without relaxing CSRF checks or exposing a separate development listener.

## Collaboration flows

- Select a joined channel, create a channel, or rejoin a known channel ID after leaving it. Rejoin does not discover private channels, enroll a new user or restore removed membership. The first owner is enrolled in `general` automatically.
- Register an agent with a descriptive role, then explicitly add it to the selected channel. A profile does not configure T3, issue an execution credential or start work. Mention choices come from current active, joined agent memberships verified by the server.
- Read channel history, start/select topics, and post attributed plain-text messages with structured agent mentions. HTML is rendered as text. Channel and topic selection survive browser refresh in the URL. A configured Inbox may deliver mentions under its separate explicit deployment policy; the UI does not bypass that policy or call T3.
- Create a task with acceptance criteria, optional owner and distinct reviewer. Claim a proposed task as yourself, update your progress, request a review from a joined member, or explicitly hand off work. Responsibility is always evaluated by the server; a human cannot impersonate an agent to complete its transitions.
- The actual assigned reviewer may approve technical review or request changes. The designated human acceptor separately accepts an awaiting-human task or requests rework. No provider success or UI poll accepts anything. Each card binds its own immutable task ID, current expectedVersion, operation key and decision note. Activity expands persisted, attributed decision history and execution references.
- Inspect an agent's execution associations and recorded runtime reports. Waiting, failed, stopped and succeeded are distinct recorded observations with timestamps and human/agent provenance. An association is not proof that a native Run exists, nor is a reported success human task acceptance.

Agent credential issuance, profile preference editing and external Provider/OAuth configuration remain owner API/operator functions. Human invitations and arbitrary new team-member onboarding are not implemented. Current workspace administration uses the authenticated human owner policy; non-owner team membership does not imply owner privileges.

## AG-UI and refresh semantics

`GET /api/workspace` reconstructs the signed-in owner's team, joined channels, selected channel/topic message history, tasks and agent enrollment from Kinmesh-owned repositories. It accepts only bounded validated paging/filter parameters and never accepts an actor selector. Responses are `Cache-Control: no-store` and authorized through the existing server-derived principal.

`GET /api/agui/:teamId/:memberId` is a protected human-owner read. It validates current membership through the identity repository and returns **one official AG-UI 1.0 STATE_SNAPSHOT event**. Both construction and browser decoding use `@ag-ui/core/schemas`; the Kinmesh snapshot payload has its own strict Zod schema. It contains `source: kinmesh-persisted-reports`, snapshot-read time, the agent profile, execution references and attributed runtime observations. Persistent AgentId is never an AG-UI invocation ID, and ChannelId is never a T3 ThreadId.

These are HTTP snapshots, **not a run-event/token stream or fresh native T3 verification**. No RUN_STARTED/RUN_FINISHED, text deltas, tool activity or native approval controls are synthesized. The workspace polls every 15 seconds, refreshes after successful actions, and supports an explicit **Reconnect / refresh** button and browser-online recovery. A failed refresh marks the old snapshot disconnected and disables data-changing controls until a successful reload. Agent execution snapshots independently show a retry error if unavailable. Session expiry clears the workspace.

Responses show at most 100 channels/profiles, 50 messages/topics/tasks per page, and 20 execution associations with 100 reports each. Page controls use the existing bounded snapshot cursors; refresh begins reconstruction again and cannot turn a paged history into a token stream. Truncation is labeled. Full agent/execution history remains available through the authenticated APIs. The workspace projection bounds agent and execution reads in SQLite. Associations and reports use persisted append order, so tied wall-clock timestamps do not invent a newer observation.

There is no stored, verified native launch URL on a correlation. **Open in T3** is therefore disabled with an explanation while exact environment/thread/Run references remain visible. A future authorized, validated native link resolver is needed; the UI never guesses a deep-link path or exposes an OAuth endpoint/token.

## Errors and idempotency

Browser API requests use same-origin credentials and server Origin checks. Static/API responses carry restrictive CSP, no-referrer and nosniff headers. React text rendering escapes team content; no raw HTML renderer is used. No T3 OAuth file, provider login, Agent grant or private prompt is sent to the browser.

Mutation forms create supported DTOs with a new operationKey for a new logical action; task commands carry the rendered expectedVersion. HTTP 403/409/429 and authentication errors are shown explicitly, without optimistic success. A network-ambiguous mutation retains the exact submitted request/key in component memory, disables editing and offers an explicit **Retry same action**. It is not automatically resent. Reloading discards unsent/retry form memory; inspect durable state before creating another logical action. Unkeyed profile registration is protected by the existing team-name uniqueness rule; a lost-response retry can return 409, requiring inspection. Setup/login are not domain idempotency operations.

## Browser checks

```sh
npm ci
npx playwright install --with-deps chromium
npm run build
npm run test:browser
```

Playwright launches real Chromium against disposable Fastify subprocesses and SQLite databases, with generated local secrets and a minimal environment excluding Inbox/T3 credentials. Tests fail if browser installation/launch/interaction fails; there is no HTTP-only fallback. CI installs Chromium explicitly. Browser tests exercise desktop/mobile setup/login, channels, enrollment, topics, persistent messages/mentions, refresh/offline reconnect, independent task decisions, owner acceptance/rework, protected AG-UI snapshots, schema-valid persisted execution reports and security denials. Agent actions in responsibility tests use an independent local scoped HTTP client; execution-reference fixtures are explicitly synthetic and never native model evidence. Browser traces/videos are off to keep authentication material out of artifacts.

The ordinary `npm run check`, `npm run format:check`, `npm run build` and production audit remain required. Browser tests use no T3 installation, OAuth or paid models. Real native status refresh, verified original-T3 links and automatic worker/provider acceptance require their separate authorized integration gates.
