# T3 owner acceptance — 2026-10-30

## Scope and authority

Issue [#2](https://github.com/ronhuafeng/kinmesh/issues/2) requires an execution adapter over the supported external interface of unchanged T3. The owner authorized Mac-based acceptance over their remote HTTPS MCP endpoint, approved separate Read only and Supervised OAuth grants in the native browser page, and selected a two-Run budget using `codex` / `gpt-6.1-sol`. They replaced the original 1000-line interruption prompt with a maximum of 200 characters. The later compatibility and lifecycle probes use idle threads without messages: no additional model Runs.

Keep these evidence sets separate:

1. **Owner path:** Mac, Node 24.16.0, official MCP SDK 1.32.2, remote HTTPS T3 Connect, unchanged Linux T3 0.1.5, human browser consent.
2. **Isolated compatibility path:** official unmodified Linux release binaries, disposable data directories and projects, loopback-only servers, SSH forwarding, official SDK/OAuth and `T3Backend`. Native CLI commands prepare and dispose the test environments; execution operations still use MCP. Native pairing consent on this test-owned issuer is automated and is **not** additional human browser evidence.
3. **Controlled local tests:** fixtures and subprocess tests; these are not additional external-platform observations.

No T3 implementation was imported, patched, rebuilt or vendored. No private T3 database or WebSocket was read. The shared server's version, network settings, providers and linked-environment setting were not changed. No extra T3 Connect tunnel was created. Grants, callback URLs, pairing codes, provider output, private endpoints and stable environment/thread IDs are excluded from this public record.

The isolated older binary was downloaded from the official 0.1.4 release and verified against its published SHA256SUMS. Tests do not claim compatibility with an unreleased newer version.

The shared instance has Linked environments disabled. Its native CLI correctly refused linking. Rather than enable a shared feature for a test, the probes use isolated instances with their own explicit feature configuration and narrowly scoped test OAuth grant. A plain CLI-issued bearer session was correctly refused by MCP; it was not disguised as OAuth. All successful isolated adapter probes use actual SDK registration, PKCE and native pairing-code OAuth.

## Limits

- The character instruction is not a hard token, duration or monetary cap. A short response that completes before interruption does not prove interruption.
- Project/linked probes validate identity and workspace selection without starting a model there; the real model lifecycle was witnessed on the owner's scratch thread.
- Idle-thread recovery does not establish what happens to an active provider process during a T3 restart. Controlled recovery and cancellation tests cover internal adapter branches; they do not replace every external failure scenario.
- No dedicated authenticated GitHub runner, Team MCP provider collaboration gate, Inbox gate, multi-user deployment or blanket release acceptance is claimed here.
- Unsupported versions must still be rejected until their public schemas and real compatibility evidence are reviewed. Keep T3 independently deployed.
