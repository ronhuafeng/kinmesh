## Product defect found and repaired

A real SQLite counterexample showed that an Agent's valid review handoff could make its own original Inbox delivery lose permission to finish publication. Reviewer approval had the same problem. A later retry could be blocked before reading its already launched native execution.

PR #37 separates authority to launch new work from authority to settle an existing journaled attempt. Settlement still requires the original event recipient, a retained owner/reviewer responsibility, the frozen scope and original native operation, current grants/membership and the current claim fence. Cancellation, role reassignment away from the Agent and grant revocation still deny publication. A frozen request without a dispatching/uncertain/known native journal entry does not grant launch authority.

Inbox publication records the immutable execution association without making a new task decision or incrementing the task's business version. The explicit public versioned execution-link command is unchanged. The repair also preserves PR #36's reuse of an already linked exact execution and adds an explicit task activity refresh button without per-card polling.

The exact final repair head was independently reviewed on specification and repository standards; the review was an AI code review, not a human approval. See [the published review](https://github.com/ronhuafeng/kinmesh/pull/37#pullrequestreview-5721437888).
