# T3 and Team MCP

Kinmesh talks to the outside world through two narrow interfaces: the **T3 adapter**, which runs agents on independently installed, unmodified T3 Code, and **Team MCP**, which lets those agents act in Kinmesh. Neither embeds the other. Kinmesh never imports T3 code or uses T3's private packages, databases or WebSockets, and the product never shells out to T3's CLI; `npm run architecture` guards this statically. Running the gates that exercise both against real T3 is in [operations](operations.md#live-and-native-gates).

## T3 adapter

`src/domain/execution.ts` owns `ExecutionBackend`: project or scratch targets, operation intent, stable environment/thread/run references, normalized observations and discriminated dispatch, wait and stop results. `src/adapters/t3` implements it with the official MCP SDK (Streamable HTTP and OAuth), Zod and Ajv. There is no unauthenticated execution API; the [Inbox](collaboration.md#agent-inbox) is the only caller in the product.

### Supported T3

Kinmesh supports **T3 0.1.5 or newer**. The environment descriptor must report a plain `major.minor.patch` version at or above that floor, and every tool call is validated against the JSON schemas T3 advertises; a missing tool or schema, or an incompatible reply, fails closed as `incompatible`. Adopting a T3 release with a changed MCP contract means reviewing its schemas and running the [native gates](operations.md#live-and-native-gates) against it; fix the adapter, never T3.

### Endpoints

Use the exact canonical `https://host/mcp` URL from T3 **Settings → Environments → environment menu → Copy MCP URL**, without userinfo, query or fragment. Plain HTTP is allowed only on loopback. The endpoint must be reachable from both the machine that holds the credential and the owner's browser: a host-local `http://127.0.0.1:3773/mcp` produces an authorization page on the browser computer's own loopback. Never rewrite an issued authorization URL to work around this.

### Preflight

```sh
KINMESH_T3_ENDPOINT=https://your-t3.example/mcp npm run --silent t3:preflight
```

Preflight reads only `KINMESH_T3_ENDPOINT` and needs no credential. Under one 10-second deadline it checks that unauthenticated `/mcp` answers 401 with a Bearer challenge, that the public environment descriptor names an environment on a supported version, and that the pinned OAuth metadata offers S256 PKCE, issuer in the authorization response, the authorization-code grant for public clients, and the `orchestration:read` and `orchestration:operate` scopes. Discovery is same-origin, GET-only, refuses redirects, bounds JSON to 64 KiB and sends no cookies or authorization. Output is fixed PASS/FAIL text. Preflight never registers a client, opens consent, calls a tool or runs a model.

### Owner sign-in

Kinmesh holds its **own** T3 OAuth grant; provider logins, Team MCP credentials and T3's native pairing are separate. Only the owner approves, on T3's consent page: choose **Supervised** for agents that run, or **Read only** for inspection; never Full access. T3 may ask for a pairing code from **Settings → Sharing & access**; it must come from the environment serving the chosen endpoint. Revoke or rotate grants there too.

**From the workspace.** The agent page connects T3 once per team (UI in [DESIGN.md](design/DESIGN.md#components)). The hub probes only the fixed loopback address `127.0.0.1:3773` for a local T3 desktop and accepts it only if it returns a valid environment descriptor; otherwise the owner pastes the MCP URL. The approval URL goes only to the owner's browser. The resulting credential is stored as described in [security](security.md#hub-held-worker-secrets) and is replaced only when the owner asks. One sign-in runs at a time, because the callback port is fixed.

| Route (owner session only)                           | Purpose                                                                 |
| ---------------------------------------------------- | ----------------------------------------------------------------------- |
| `GET /api/teams/:teamId/t3`                          | Connection, its access (`operate`, `read` or none), sign-in state       |
| `GET /api/teams/:teamId/t3/local`                    | The local T3 endpoint, if one answers                                   |
| `POST /api/teams/:teamId/t3/connect`                 | `{endpoint,replace}`; starts sign-in, returns the approval URL          |
| `GET /api/teams/:teamId/t3/providers`                | Providers and models the connected T3 can run                           |
| `POST /api/teams/:teamId/agents/:agentId/connect`    | `{providerId,modelId}`; issues the worker credential, starts the worker |
| `POST /api/teams/:teamId/agents/:agentId/disconnect` | Revokes the worker credential and removes its file                      |

**From a terminal**, for a worker the operator runs:

```sh
KINMESH_T3_ENDPOINT=https://your-t3.example/mcp \
KINMESH_T3_AUTH_FILE=/private/kinmesh/t3-oauth.json npm run t3:auth
```

The default `browser` mode listens on `http://127.0.0.1:49871/callback` and opens the approval page without printing its URL. With no local browser, set `KINMESH_T3_AUTH_MODE=manual` in the owner's private interactive terminal on the target machine (never through an agent tool, CI, a recorder or redirected output). Manual mode refuses non-TTY use and writes the one-time URL only to `/dev/tty`. Open it in a browser, approve, then paste the **complete final address-bar URL** (the browser's failed load of `127.0.0.1:49871` is expected) into the hidden prompt. Authorization codes expire within about a minute; the whole flow has a three-minute deadline. Failed attempts are not retried; start again.

Both modes accept exactly one `state`, `code` and `iss` on the exact callback, matching the random state and pinned issuer, and reject everything else. The SDK owns discovery, dynamic registration, S256 PKCE and exchange. The CLI refuses any existing destination file and writes a new 0600 file atomically; it prints no token, registration secret or verifier.

### Smoke check

```sh
KINMESH_T3_ENDPOINT=https://your-t3.example/mcp \
KINMESH_T3_AUTH_FILE=/private/kinmesh/t3-oauth.json npm run t3:smoke
```

The smoke check initializes MCP, lists tools, and calls only `t3_environment_read` and `orchestrator_capabilities`. It validates the environment, version and schemas, reports whether the grant includes `orchestration:operate`, and requires the `approval-required` capability ceiling for an operate grant. It never launches a thread, runs a model or writes the journal. A Read only grant passes but cannot run agents.

Credential files follow the [T3 credential rules](security.md#t3-credentials). Expired or revoked grants need a new owner sign-in.

### Operations

| Domain operation | T3 tool and semantics                                                                                                         |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Connect          | `t3_environment_read`, `orchestrator_capabilities`, `tools/list`; pins environment identity and version                       |
| Launch           | `t3_thread_launch`: project ID **or** `scratch: true`, advertised provider/model, explicit permission mode, `clientRequestId` |
| Read             | `t3_thread_read`: thread, `recentRuns`, bounded message pages with explicit truncation                                        |
| Follow-up        | `t3_thread_send` in queue mode with a persisted key; no silent steer or restart                                               |
| Wait             | `t3_thread_wait`, 1–20000 ms; `timedOut` is not completion; followed by an authoritative read                                 |
| Stop             | `t3_thread_interrupt` for the run; acknowledgement is not terminal; a read decides                                            |
| Reconcile        | Stored reference → read; otherwise replay the same persisted command and key, then read                                       |

A read selects the requested run from `recentRuns`; a run outside T3's latest 50 is `unobserved`, never another run's status. `completed` maps to `succeeded`; `interrupted`, `cancelled` and `rolled_back` to `stopped`; `waiting` stays nonterminal. Acceptance is always `not-evaluated`. Live harnesses also call `t3_thread_organize` to archive their own threads.

### Durable operations and recovery

The `execution_operations` table records, per endpoint/environment scope, actor and caller `operationKey`: the input and OAuth-authority fingerprints (hashes, not tokens), a random stable native request ID, tool and payload, phase and any reference. Intent is persisted **before** dispatch. A claim takes a generation, random token and 120-second lease in one SQL compare-and-set; every journal write checks them against SQLite time, so an expired or superseded owner cannot overwrite a newer outcome. There is no heartbeat; a crashed process's lease simply expires.

| Phase / outcome                                                        | Safe next action                                                          |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `prepared`                                                             | Claim and dispatch the persisted request ID                               |
| `dispatching`, crash, lost reply, timeout, cancellation in flight      | Return `uncertain` with the operation ID; reconcile, never mint a new key |
| Valid reply, read fails                                                | Keep the provisional reference; reconcile by read only                    |
| Valid reply, matching run/thread                                       | Mark `known`; duplicates get the stored reference                         |
| Native `capability_denied` or HTTP auth rejection before a valid reply | Persist the rejection and fail; generic errors are not denial             |
| Unsupported version or missing `clientRequestId`                       | Fail before mutation                                                      |
| Different authority fingerprint                                        | Conflict; the owner resolves the existing intent                          |

Same key with different input is a conflict. SDK requests time out after 30 seconds and each attempt has a 60-second deadline, inside the lease. T3's own idempotency on the request ID is the cross-system deduplication; the lease only serializes Kinmesh. An aborted wait does not stop T3 work; use an explicit stop. Keep the host clock synchronized. The journal may contain prompts; protect it as team data.

### Checking a run

An owner can ask T3 for the live state of a recorded run (**Check in T3** on the agent page). It reads through the team's T3 connection — the one approved with **Connect T3** — so there is nothing else to configure; before a team connects T3, checking isn't offered. The check uses only read tools (`orchestration:read` is enough), never operating tools, and never acquires or renews tokens.

`GET /api/teams/:teamId/agents/:agentId/executions/:executionId/native` requires an owner session. The server loads the exact stored association before reading any credential; nothing in the request chooses the endpoint, credential, environment or thread. It calls only `t3_environment_read` and `t3_thread_read` under an eight-second deadline, refuses redirects, rechecks owner access after the read and never stores the result. Any native failure is the same generic 503. The result is a timestamped read of the run's exact status; pending requests are thread-scoped.

An **Open in T3** link appears only when T3 returned `thread.link` and the server matched it to the team's T3 origin and the exact environment and thread; Kinmesh never builds a URL from IDs. The snapshot exposes only that origin (`nativeT3Origin`). A T3 browser may still need its own pairing to show the thread.

## Team MCP

Team MCP is a standalone agent-only service over Kinmesh's repositories, separate from T3's MCP. It uses `@modelcontextprotocol/sdk` stateless Streamable HTTP with Zod schemas and adds no tables.

### Setup

```dotenv
KINMESH_DATABASE=.store/kinmesh.sqlite      # the hub's database
KINMESH_TEAM_MCP_PORT=3001
KINMESH_TEAM_MCP_ORIGIN=http://127.0.0.1:3001
KINMESH_TEAM_MCP_CONCURRENCY=16             # 1–64
KINMESH_TEAM_MCP_ENDPOINT=http://127.0.0.1:3001/mcp   # for team:smoke
KINMESH_TEAM_MCP_TOKEN_FILE=.store/team-agent.json    # for team:smoke
```

```sh
npm run team:mcp     # separate process, same database as the hub
npm run team:smoke   # read-only SDK check: initialize, ping, list, channel read
```

Issue the agent a grant with only the scopes it needs ([scopes](collaboration.md#grants-and-scopes)); the agent page issues one with channel and task scopes. Save it as `{"token":"…"}` in a 0600 file. The service applies migrations, needs no setup or session secret, and prints no credentials or content. The smoke CLI rejects unsafe token files, endpoints and redirects and prints fixed PASS/FAIL.

### Transport and authority

`POST /mcp` creates and closes an SDK server per request; there are no sessions, streams or resumption, and GET/DELETE return 405. Every request needs `Authorization: Bearer <agent-token>`; missing, expired, disabled or revoked credentials get 401 with `WWW-Authenticate: Bearer realm="kinmesh-team"`. Each tool call resolves the bearer again, and repositories check scope, team, channel and task authority in their transaction. The team comes only from the grant; the actor never comes from arguments, metadata or roles. Human cookies and actor headers are rejected. Accept, rework, cancel, membership and credential administration are not offered. Network limits are in [security](security.md#team-mcp).

Remote clients reach the loopback listener through a same-host HTTPS reverse proxy: set `KINMESH_TEAM_MCP_ORIGIN=https://team.example` and use `https://team.example/mcp`. Team MCP authenticates with Kinmesh bearer grants, not OAuth; OAuth-only clients cannot connect.

### Tools

| Tool                       | Input beyond shared fields                       | Authority                                     |
| -------------------------- | ------------------------------------------------ | --------------------------------------------- |
| `team_channels_list`       | Optional limit/cursor                            | `channels:read`; joined channels only         |
| `team_channel_get`         | channelId                                        | `channels:read` + joined                      |
| `team_topics_list`         | channelId, optional limit/cursor                 | `channels:read` + joined                      |
| `team_topic_create`        | channelId, operationKey, title                   | `channels:write` + joined                     |
| `team_messages_read`       | channelId, optional topicId/limit/cursor         | `channels:read` + joined                      |
| `team_message_get`         | channelId, messageId                             | `channels:read` + joined                      |
| `team_messages_send`       | channelId plus post input                        | `channels:write` + joined                     |
| `team_tasks_list`          | channelId, optional limit/cursor                 | `tasks:read` + channel access                 |
| `team_task_get`            | channelId, taskId                                | `tasks:read` + channel access                 |
| `team_tasks_history`       | channelId, taskId, optional limit/cursor         | `tasks:read` + channel access                 |
| `team_task_executions`     | channelId, taskId, optional limit/cursor         | `tasks:read` + channel access                 |
| `team_task_create`         | channelId plus task create input                 | `tasks:write`; unowned or self-owned          |
| `team_task_claim`          | channelId, taskId, operationKey, expectedVersion | `tasks:write`                                 |
| `team_task_progress`       | Command fields + note                            | Work owner; `tasks:write`                     |
| `team_task_handoff`        | Command fields + recipient, mode, note           | Work owner; `tasks:write`                     |
| `team_task_request_review` | Command fields + reviewer, note                  | Work owner; `tasks:write`                     |
| `team_task_review`         | Command fields + decision, note                  | Assigned reviewer; `tasks:review`             |
| `team_task_link_execution` | Command fields + reference, note                 | Work owner or pending reviewer; `tasks:write` |

Command fields are channelId, taskId, operationKey and expectedVersion; the tool names the action. Inputs, receipts, cursors and transitions are those of the [HTTP API](collaboration.md). Results carry `structuredContent` and the same JSON as text:

```text
{"result":{"ok":true,"data":<validated DTO or page>}}
{"result":{"ok":false,"error":{"code":"forbidden","message":"Permission denied"}}}
```

Expected failures set `isError: true` with a fixed code (`invalid_input`, `unauthenticated`, `forbidden`, `not_found`, `conflict`, `internal`) and no protected data. Unknown tools and invalid schemas get the SDK's standard errors. A network failure is never proof of denied authority. Retry an ambiguous mutation with the same key and input. Every authenticated request records the agent's Team MCP presence for the workspace; presence is evidence, not authority.

### Provider configuration

A provider reaches Team MCP with the URL and the agent's bearer credential, configured through the provider's own supported settings. For Codex, use `mcp_servers.<name>` with `url` and `bearer_token_env_var` (or an HTTP header), keeping the token in a protected environment or file. T3's `t3_thread_launch` has no field for per-run MCP credentials, so the provider must already be configured for its agent. Kinmesh never edits provider homes or settings. Keep T3 in `approval-required` mode and never treat model feedback as human acceptance.

Agents connected from the workspace may run on any provider T3 offers; Team MCP is optional for them. Operator-configured worker bindings assert with `externalTeamMcpConfigured: true` that their isolated provider was configured; Kinmesh cannot verify that remotely.
